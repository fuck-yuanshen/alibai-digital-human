# 语音输入功能问题说明与解决方案

## 问题现象

用户点击语音输入按钮后，提示"浏览器语音识别服务不可用，请检查网络后重试"。

## 问题根源

### 架构设计

该项目的语音输入功能采用**前端识别**架构：

```
用户说话 → 浏览器麦克风 → Web Speech API → Google语音服务 → 识别结果 → 发送到后端
```

关键代码位置：`static/client_talk.js:539-633`

```javascript
setupSpeechRecognition() {
    const SpeechRecognition = window.SpeechRecognition || window.webkitSpeechRecognition;
    this.recognition = new SpeechRecognition();
    this.recognition.lang = 'zh-CN';
    // ...
}
```

### 核心问题

1. **依赖外部服务**：浏览器的 Web Speech API 需要连接 Google 的语音识别服务器
2. **网络限制**：在无法访问 Google 服务的网络环境下，会报 `network` 错误
3. **后端 ASR 误解**：项目中的 `LipASR` 类（`src/lipasr.py`）仅用于从 TTS 生成的音频中提取唇形同步特征，**不是实时语音识别服务**

## 当前架构说明

### 前端（client_talk.js）
- 使用 Web Speech API 进行语音识别
- 识别结果通过 `/human` 接口发送到后端
- 完全依赖浏览器的语音识别能力

### 后端（main.py + src/）
- `LipASR`：仅处理 TTS 音频的梅尔频谱特征提取（用于唇形同步）
- 没有独立的实时语音识别服务
- 无法接收和识别客户端的实时语音流

项目已经集成了 DashScope TTS，可以复用其 API 来实现语音识别。

#### 实现步骤

**1. 安装依赖**
```bash
pip install dashscope
```

**2. 添加 ASR 配置到 config.yml**
```yaml
ASR:
  DASHSCOPE_ASR_MODEL: "paraformer-realtime-v2"
  DASHSCOPE_ASR_FORMAT: "pcm"
  DASHSCOPE_ASR_SAMPLE_RATE: 16000
```

**3. 创建 DashScope ASR 服务**

创建文件 `src/dashscope_asr.py`：

```python
import dashscope
from dashscope.audio.asr import Recognition
import numpy as np
from queue import Queue
import threading
from src.log import logger
from src.config import get_dashscope_api_key

class DashScopeASR:
    def __init__(self, callback):
        """
        callback: 识别结果回调函数 (text: str) -> None
        """
        self.api_key = get_dashscope_api_key()
        self.callback = callback
        self.audio_queue = Queue()
        self.running = False
        self.thread = None
        
    def start(self):
        """启动语音识别"""
        if self.running:
            return
        self.running = True
        self.thread = threading.Thread(target=self._recognition_loop)
        self.thread.start()
        logger.info("DashScope ASR started")
    
    def stop(self):
        """停止语音识别"""
        self.running = False
        if self.thread:
            self.thread.join()
        logger.info("DashScope ASR stopped")
    
    def put_audio(self, audio_data: np.ndarray):
        """
        接收音频数据（16kHz, 单声道, float32）
        audio_data: numpy array, shape (samples,)
        """
        self.audio_queue.put(audio_data)
    
    def _recognition_loop(self):
        """识别循环"""
        recognition = Recognition(
            model='paraformer-realtime-v2',
            format='pcm',
            sample_rate=16000,
            api_key=self.api_key
        )
        
        while self.running:
            try:
                # 收集音频数据
                audio_chunks = []
                while not self.audio_queue.empty():
                    audio_chunks.append(self.audio_queue.get())
                
                if not audio_chunks:
                    continue
                
                # 合并音频数据
                audio_data = np.concatenate(audio_chunks)
                
                # 转换为 PCM 字节流
                audio_bytes = (audio_data * 32767).astype(np.int16).tobytes()
                
                # 调用识别
                result = recognition.call(audio_bytes)
                
                if result.status_code == 200:
                    text = result.output.get('text', '').strip()
                    if text:
                        logger.info(f"ASR result: {text}")
                        self.callback(text)
                else:
                    logger.error(f"ASR error: {result.message}")
                    
            except Exception as e:
                logger.error(f"ASR recognition error: {e}")
```

**4. 修改后端接收音频轨道**

修改 `src/basereal.py`，添加音频接收处理：

```python
def set_client_audio_track(self, audio_track):
    """设置客户端音频轨道用于语音识别"""
    from src.dashscope_asr import DashScopeASR
    
    self.client_audio_track = audio_track
    
    # 创建ASR实例
    self.asr_service = DashScopeASR(callback=self._on_asr_result)
    self.asr_service.start()
    
    # 启动音频处理任务
    if self.data_channel_loop:
        self.client_audio_task = self.data_channel_loop.create_task(
            self._process_client_audio()
        )

def _on_asr_result(self, text: str):
    """ASR识别结果回调"""
    logger.info(f"Voice input: {text}")
    
    # 通过数据通道发送识别结果到前端
    self.send_data_channel_message({
        'type': 'asr',
        'text': text
    })
    
    # 触发LLM对话
    from src.llm import llm_response
    import asyncio
    asyncio.get_event_loop().run_in_executor(
        None,
        llm_response,
        text,
        self
    )
```

## 已实施的稳定修复

原先的方案仍依赖浏览器 `SpeechRecognition`，即使前端显示“后端 ASR 模式”，后端也只是把麦克风帧放进唇形同步队列，并没有调用语音识别服务。现在已改为下面的链路：

```
浏览器麦克风 → WebRTC 音频轨道 → 后端 AudioResampler
            → 16 kHz/单声道/PCM16 → DashScope Recognition
            → 句末文本 → /human 等价的 LLM/TTS 流程
```

具体实现：

- `src/dashscope_asr.py` 封装 `paraformer-realtime-v2`，只在句末回调一次最终文本，避免同一句话重复触发 LLM。
- `src/basereal.py` 持续消费 WebRTC 音频，使用 PyAV 将浏览器常见的 48 kHz/立体声帧统一成 16 kHz/单声道 PCM16；未开始说话时只消费不上传，避免 WebRTC 接收缓冲堆积。
- `main.py` 增加 `/voice/start`、`/voice/stop` 控制接口，并支持数据通道控制消息；ASR 会话按用户操作启停。
- `static/client_talk.js` 不再创建浏览器 Web Speech 识别器，启动语音前先确认后端 ASR 成功，停止时保留 SDK 最后的句末事件，避免丢掉最后一句。
- `config.yml` 增加 ASR 模型、格式和采样率配置；密钥仍只从 `.env` 的 `DASHSCOPE_API_KEY` 读取。
- 页面脚本版本已更新为 `20260915-backend-asr-v1`，避免浏览器继续使用旧的在线识别脚本。
